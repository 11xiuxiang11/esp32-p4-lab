# 01 · 任务与调度

## 一句话总结

**调度器只做一件事：每个核跑"就绪任务里优先级最高的那个"。优先级是排队顺序，不是加速开关。**

---

## 概念

### 任务是什么

任务 = **一个永不返回的函数 + 一块独立栈 + 一个 TCB**（任务控制块，内核记档案用的结构体）。

### 三种时间，别混

| 名字 | 谁决定 | 用途 |
|---|---|---|
| **tick** | `CONFIG_FREERTOS_HZ=100` → **1 tick = 10ms** | 内核的计时单位 |
| **时间片** | 内核，10ms | 同优先级任务之间多久轮换一次 |
| **周期** | 你自己的 `vTaskDelayUntil` | 这个任务多久跑一轮 |

**内核里没有"周期"这个概念**，它只知道"这个任务在 tick = N 时该被叫醒"。

### 任务状态

```
        创建
         ↓
      就绪 ──(被调度)──→ 运行 ──(被抢占)──→ 就绪
         ↑                │
         │             (等时间/等队列/等信号量)
         └──── 阻塞 ←────┤
                         ↓
                      (vTaskDelete) → 删除
```

### 四种切换时机

1. 自己阻塞（`vTaskDelay` / 等队列 / 等信号量）
2. 被同核更高优先级任务抢占
3. 同优先级时间片用完
4. 主动 `taskYIELD()`

> 切换的落点永远是"中断出口"，不是任务执行到一半被硬切。RISC-V 移植层的 `rtos_int_exit` 里才真正换人（`xPortSwitchFlag[core]` 是请求旗子）。

### 双核

- 每个核有**自己的**调度器实例和"当前任务"
- 就绪链表、延时链表是**共享**的，访问要自旋锁
- 绑核靠 `xTaskCreatePinnedToCore` 的最后一个参数
- **双核不会自动并行**：不绑核 / 绑同一个核，就还是排队

### 两种"忙等"的区别（本节最值钱的一条）

| 写法 | 计时依据 | 被抢占时 |
|---|---|---|
| `while (esp_timer_get_time() - t0 < 60ms) {}` | **墙钟** | 墙钟照样走，照样 60ms 后退出 → 活只干了一部分 |
| `for (i=0; i<2643120; i++) {计算}` | **CPU 时间** | 算不完就得超期 → 周期漂移 |

## 代码

### 创建任务（七参数，口诀：函数、名字、栈、参数、优先级、句柄、核）

```c
BaseType_t ret = xTaskCreatePinnedToCore(
        worker_task,        /* ① 任务函数 */
        "TASK_A",           /* ② 名字（最长 16 字符） */
        4096,               /* ③ 栈大小，单位【字节】！ */
        &s_cfg_a,           /* ④ 传给任务的参数（void*） */
        5,                  /* ⑤ 优先级，0~24，越大越优先 */
        &s_handle_a,        /* ⑥ 句柄（可为 NULL） */
        0);                 /* ⑦ 绑到哪个核 */
if (ret != pdPASS) { ESP_LOGE(TAG, "创建失败"); abort(); }
```

### 周期任务

```c
TickType_t last_wake = xTaskGetTickCount();
while (1) {
    do_work();
    vTaskDelayUntil(&last_wake, pdMS_TO_TICKS(100));  /* 固定周期，不漂移 */
}
```

- `vTaskDelayUntil`：下一次唤醒 = 上次 + 周期 → **周期任务用它**
- `vTaskDelay`：从现在起等 N tick → **间隔任务用它**

### 查状态

```c
xPortGetCoreID();                            /* 当前在哪个核 */
uxTaskPriorityGet(NULL);                     /* 优先级 */
uxTaskGetStackHighWaterMark(NULL);           /* 栈历史最低剩余（字节） */
vTaskGetRunTimeStats(stats_buf);             /* 各任务 CPU 占比（需开配置） */
```

`vTaskGetRunTimeStats` 需要 `sdkconfig` 里：
```
CONFIG_FREERTOS_GENERATE_RUN_TIME_STATS=y
CONFIG_FREERTOS_USE_TRACE_FACILITY=y
```

### 任务函数必须这样收尾

```c
static void worker_task(void *arg)
{
    while (1) { ... }        /* 死循环，或者 */
    vTaskDelete(NULL);       /* 干完自己删自己 —— 绝对不能 return */
}
```

## 实测数据（`p4-lab/main/main.c`）

| 场景 | 结果 |
|---|---|
| 两任务同核、优先级都 5、各忙 40ms/100ms | A 39% / B 39% / IDLE0 19%，周期精确 100ms |
| 把 B 优先级改成 6 | **什么都没变**（没超载，不用排队） |
| 各忙 60ms（总 120%，墙钟计时） | 周期仍 100ms，但 **`task_wdt` 每 5s 报 IDLE0 饿死** |
| 改成按计算量（总 120%） | 周期 100 → **119ms**（理论 120ms），WDT 照旧 |
| 启动标定 | 1ms CPU ≈ 44052 次迭代；每轮 264 万次 |

## 易错处

| # | 错误 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 以为栈单位是"字"（原生 FreeRTOS 语义） | 栈只有 1/4 大小 → 溢出 | **ESP-IDF 里是字节**，头文件原文写明 "NUMBER OF BYTES. Note that this differs from vanilla FreeRTOS." |
| 2 | `vTaskDelay(1)` 想延时 1ms | 实际 10ms | 1 tick = 10ms，用 `pdMS_TO_TICKS(1)` 也是 1 tick |
| 3 | 任务函数 `return` | 踩 `prvTaskExitError` 断言 → 板子重启 | `vTaskDelete(NULL)` 或死循环 |
| 4 | 以为优先级高就跑得快 | 没超载时毫无变化 | 优先级只决定排队顺序 |
| 5 | 以为创建了两个任务就在并行 | 可能被高优先级任务抢占，第二个还没创建 | 创建期间临时提高创建者优先级，或用信号量同步启动 |
| 6 | 只在启动时看栈水位 | 数字偏乐观 | 系统满载跑一段时间后再看 |
| 7 | 周期任务用 `vTaskDelay` | 周期 = 干活时间 + 延时，越长越漂 | 用 `vTaskDelayUntil` |
| 8 | 忙等写 "墙钟 60ms" 却当成 60ms 的活 | 超载时表现为 WDT 而不是周期漂移，掩盖真实问题 | 区分墙钟时间与 CPU 时间 |

## 自测

1. 两个任务同核同优先级、各自 40ms 忙 / 100ms 周期，为什么周期不会互相拖慢？
2. 什么情况下优先级才会"显形"？
3. `task_wdt` 报 IDLE0，说明什么？为什么不是"崩溃"？
4. 墙钟计时和 CPU 计时，同一个 120% 负载会呈现哪两种不同现象？
