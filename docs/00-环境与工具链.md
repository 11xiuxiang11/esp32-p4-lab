# 00 · 环境与工具链

## 一句话总结

**`build` 只碰电脑，`flash` 才碰板子；两者之间还差一个"串口"——而串口同一时刻只能被一个程序占用。**

---

## 概念

```
你改 .c  →  build  →  build/p4_lab.bin  →  flash  →  板子 Flash  →  运行  →  串口输出
             ↑ 只动电脑                    ↑ 只在这步碰板子
```

| 概念 | 说明 |
|---|---|
| ESP-IDF | 乐鑫的框架，内含 FreeRTOS 内核、外设驱动、构建系统 |
| 组件（component） | IDF 的模块单位，每个组件有自己的 `CMakeLists.txt` 和头文件目录 |
| `sdkconfig` | 编译配置（由 `menuconfig` 或 `sdkconfig.defaults` 生成），**改它会影响整个构建** |
| 目标芯片 | 本项目是 `esp32p4`，不写会默认编成 `esp32`，烧不进板子 |

## 板子信息（本机实测）

| 项 | 值 |
|---|---|
| 芯片 | ESP32-P4 rev **v3.1**，双核 RISC-V |
| 板型 | ESP32-P4X-Function-EV-Board（P4 + C6） |
| USB 串口 | USB-Serial/JTAG，`VID:PID = 303A:1001`，端口名可能变（COM3 / COM4…） |
| MAC | `e8:f6:0a:**:**:**`（示例，实际以本机为准） |
| 屏 | MIPI-DSI，JD9165，1024×600 |

## 代码/命令

### 一键脚本（推荐）

```bat
.\idf.bat build                    :: 只编译
.\idf.bat -p COM3 flash            :: 只烧录（用 build 里现成的 bin）
.\idf.bat -p COM3 flash monitor    :: 烧完直接看串口
.\idf.bat -p COM3 monitor          :: 只看串口（不会重新烧）
```

背景：PowerShell 执行策略禁止 dot-source `export.ps1`，且每次新终端环境变量都会丢。
所以 `idf.bat` 转发给 `idf.ps1`，由它一次性导好环境（`-ExecutionPolicy Bypass` 只对这一次进程生效，不改系统设置）。

### 手动配方（脚本坏了时用）

```powershell
$idf = "E:\idf\idf5.5.3\v5.5.3\esp-idf"
$py  = "E:\idf\tools\python_env\idf5.5_py3.11_env\Scripts\python.exe"
Set-Location $idf
$env:IDF_PATH = $idf
$env:IDF_TOOLS_PATH = "E:\idf\tools"
& $py "tools\idf_tools.py" export --format key-value | ForEach-Object {
  if ($_ -match '^([A-Za-z_][\w]*)=' + '(.*)$') { Set-Item -Path "env:$($Matches[1])" -Value $Matches[2] }
}
Set-Location <工程目录>
& $py "$idf\tools\idf.py" build
```

### 日志过滤

```bat
.\idf.bat -p COM3 monitor | findstr "RACE"
```

## 实测数据

- 全量编译 hello_world（esp32p4）：566 个编译单元，约 2 分钟
- 增量编译（只改一个 .c）：10~20 秒
- 烧录：216 KB 镜像约 1.4 秒 + 校验

## 易错处

| 现象 | 原因 | 解法 |
|---|---|---|
| `could not open port 'COM3': PermissionError(13)` | 端口被别的程序占着（VS Code 的 monitor 最常见） | 关掉 monitor（`Ctrl+]` 或关终端） |
| `could not open port 'COM3': FileNotFoundError` | 端口不存在了——板子掉线或换了 USB 口 | 重插/换线，端口号可能变成 COM4 |
| `cmake must be available on the PATH` | 环境变量没导进来 | 用 `idf.bat`，别手动拼 |
| `.bat` 里写中文注释后报"系统找不到路径" | cmd 按 GBK 解析 UTF-8 文件，中文把行搅乱 | **bat 里只写 ASCII 注释**，逻辑放 `.ps1` |
| 改了代码行为没变 | 只 `build` 没 `flash` | build 只生成 bin，要再 flash |
| IntelliSense 满屏红波浪线，但编译通过 | 缺 `.vscode/c_cpp_properties.json`，IDE 不知道头文件在哪 | 补配置（指向 `build/compile_commands.json`） |
| VS Code 里 ESP-IDF 命令全消失 | `C:\Espressif\tools\eim_idf.json` 登记表损坏/为空（系统盘被重置时常见） | 重建登记表，见下方"扩展修复" |

### 扩展修复（2026-10 踩过）

`eim_idf.json` 需要 `version: "3.0"`，且每条安装记录自带 `idfToolsPath`：

```json
{
  "gitPath": "C:\\Program Files\\Git\\cmd\\git.exe",
  "idfToolsPath": "E:\\idf\\tools",
  "idfInstalled": [
    { "id": "idf-553",
      "path": "E:\\idf\\idf5.5.3\\v5.5.3\\esp-idf",
      "version": "v5.5.3",
      "python": "E:\\idf\\tools\\python_env\\idf5.5_py3.11_env\\Scripts\\python.exe",
      "idfToolsPath": "E:\\idf\\tools" }
  ],
  "idfSelectedId": "idf-553",
  "version": "3.0"
}
```

再在 `%APPDATA%\Code\User\settings.json` 里加 `"idf.eimIdfJsonPath": "C:\\Espressif\\tools\\eim_idf.json"`。
