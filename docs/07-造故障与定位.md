# 07 · 造故障与定位（D3）

> 四类故障，每类都按「现象 → 定位 → 根因 → 修法」记。
> 例程：`main/fault_demo.c`，入口 `RUN_EXPERIMENT = EXP_FAULT`，模式 `FAULT_MODE`。

---

## 故障一：栈溢出（`FAULT_STACK_OVERFLOW`）

### 现象（本机实测）

```
Guru Meditation Error: Core  0 panic'ed (Stack protection fault).
Detected in task "overflow" at 0x40013446
Stack pointer: 0x4ffbb1f0
Stack bounds: 0x4ffbb32c - 0x4ffbb720
```

地址翻译（`riscv32-esp-elf-addr2line -e build/p4_lab.elf 0x40013446`）：

```
0x40013446: _vfprintf_r at .../newlib/libc/stdio/vfprintf.c:654
```

**关键信息三条：**

1. `Stack protection fault` + 任务名 → canary（栈末尾魔数）被写坏
2. **SP = 0x4ffbb1f0，比栈下界 0x4ffbb32c 还小** → 栈向下溢出约 316 字节
3. 崩溃点在 **printf 内部**——`vfprintf` 自己就要几百字节栈，1KB 的任务栈调 `ESP_LOGI` 必然爆

### 定位

- `uxTaskGetStackHighWaterMark()`：历史最低剩余（字节）
- panic 里的 `Stack bounds`：这块栈的合法范围
- `addr2line`：把崩溃地址翻成函数 + 行号

### 根因

栈给太小（1KB），叠加深递归 + printf 的栈开销。

### 修法

| 做法 | 说明 |
|---|---|
| 加大栈 | 实测水位 × 1.5~2 |
| 减少深调用 | 别在任务里做递归/大局部数组 |
| 大缓冲挪走 | 用 `static` 或堆，不要放栈 |
| 日志用轻量版 | 小栈任务里避免 `ESP_LOGI` 多参数格式化 |

## 故障二：堆耗尽（`FAULT_HEAP_EXHAUST`）

### 现象

- 连续 `malloc(1024)` 到某一块失败，日志打印失败编号
- 再创建需要 32KB 栈的任务 → **创建失败**（返回 `pdFAIL`）
- 释放全部后，空闲恢复

### 定位

```c
heap_caps_get_free_size(MALLOC_CAP_INTERNAL)        /* 总量 */
heap_caps_get_largest_free_block(MALLOC_CAP_INTERNAL) /* 还能不能分配大块 */
```

### 根因

运行期无限申请、或没有释放；也可能只是需求超过内部 RAM。

### 修法

启动期一次性分配；固定块内存池；大缓冲显式 `MALLOC_CAP_SPIRAM`。

## 故障三：看门狗（`FAULT_WATCHDOG`）

### 现象

```
E (...) task_wdt: Task watchdog got triggered.
E (...) task_wdt:  - IDLE0 (CPU 0)
E (...) task_wdt: CPU 0: TASK_B
```

每 5 秒一次（`CONFIG_ESP_TASK_WDT_TIMEOUT_S=5`）。

### 定位

- 报的是"**谁没喂狗**"（IDLE0），不是"谁崩了"
- 用 `vTaskGetRunTimeStats` 看各任务 CPU 占比（两任务各 ~60%，IDLE 接近 0）

### 根因

CPU 需求 > 100%（60+60=120%），IDLE 永远排不上。

### 修法

降负载、分核（`xTaskCreatePinnedToCore(..., 1)`）、把忙等改成分段让出。

## 故障四：死锁（`FAULT_DEADLOCK`）

### 现象

**没有任何报错**，日志停在：

```
A：再拿 m2（如果卡住就是死锁）
B：再拿 m1（如果卡住就是死锁）
```

之后系统"静止"——但 IDLE 还在跑，所以**不会触发看门狗**。

### 定位

- 调试器 `info threads`：两个任务都停在 `xQueueSemaphoreTake`
- 或打印任务状态：两个任务都是 `Blocked`

### 根因

两个任务以**相反顺序**获取两把锁：A 拿 m1 等 m2，B 拿 m2 等 m1。

### 修法

1. **固定全局加锁顺序**（都先 m1 后 m2）
2. 只用一个锁
3. `xSemaphoreTake(..., 超时)`，超时后释放已持有的锁并重试

## 面试卡片（每张四句话）

**栈溢出**：现象是 panic 报 `Stack protection fault` 并指出任务名；定位看 Stack bounds 和 high water mark；根因是栈不足（含 printf 开销）；修法是加大栈/减递归/大数组挪出栈。

**堆耗尽**：现象是分配失败、任务创建失败；定位看 `largest_free_block` 而不是总量；根因是运行期无限申请或需求超内部 RAM；修法是启动期分配 + 内存池 + PSRAM。

**看门狗**：现象是 `task_wdt` 报 IDLE0；定位看运行时间统计里 IDLE 占比；根因是 CPU 需求超过 100%；修法是降负载、分核、让出 CPU。

**死锁**：现象是系统静止但**无任何报错**；定位用调试器看线程全阻塞在 take；根因是交叉加锁；修法是固定顺序或加超时。

---

1. `main.c`：`#define RUN_EXPERIMENT EXP_FAULT`
2. `fault_demo.c`：改 `#define FAULT_MODE`（0/1/2/3）
3. `idf.bat -p COM3 flash`，然后 `idf.bat -p COM3 monitor`

# 附：修法怎么下手（三步法）

> 原则：**修法不是拍脑袋，是用数字算出来，再用同一个数字验证。**

## 第一步：量

修之前先拿证据。栈类故障没法在崩溃时量，就先**给一个大栈让它跑起来**，读出实际用量：

```
8192 B 栈 + 递归 40 层 → 实测最少剩 3460 B → 实际用量约 4732 B
```

## 第二步：按规则定值

| 资源 | 定值规则 |
|---|---|
| 任务栈 | 实测用量 × 1.5~2（本次 4732 × 1.7 ≈ 8000，取 8192） |
| CPU 利用率 | Σ(busy/period) 控制在 **80% 以下**，留 20% 给 IDLE 和突发 |
| 队列长度 | 消费者处理速度 × 允许的最大积压时间 |
| 锁等待 | 给超时，值 = 业务能接受的最大延迟 |

## 第三步：用同一个指标验证

| 故障 | 验证标准 |
|---|---|
| 栈溢出 | `uxTaskGetStackHighWaterMark` 剩余 > 栈大小 × 30% |
| CPU 饥饿 | 运行统计里 IDLE > 10%，`task_wdt` 不再报 |
| 堆耗尽 | 连续跑 24h，`minimum_free_heap_size` 不下降 |
| 死锁 | 压测 1 万次，双方都能拿到锁 |
| 野指针 | 同一操作重复 1000 次不崩 + 打开 `CONFIG_HEAP_POISONING` |

## 五类故障的修法总表

| 故障 | 改哪里 | 改成多少 | 验证 |
|---|---|---|---|
| 栈溢出 | `xTaskCreate` 的栈参数 | 实测 × 1.5~2 | HWM 剩余 > 30% |
| 野指针 | 加返回值检查、指针初始化为 NULL、`assert` | — | 压测 1000 次不崩 |
| CPU 饥饿 | 分核（core=1）、降周期、拆忙等 | 利用率 < 80% | IDLE > 10% |
| 堆耗尽 | 启动期预分配、内存池、`MALLOC_CAP_SPIRAM` | 按预算表 | 24h 水位不降 |
| 死锁 | 固定加锁顺序、`take` 加超时、只用一个锁 | 超时 = 业务上限 | 压测 1 万次 |
