# 05 · 事件组与软件定时器

## 一句话总结

**事件组是"多条件位运算"（等几个条件全满足/任一满足）；软件定时器是"借别人的任务跑你的回调"——回调必须短。**

---

## 概念

### 事件组（Event Group）

一个 32 位变量，**可用 bit 0~23（24 个）**，高位被内核占用。

| API | 用途 |
|---|---|
| `xEventGroupCreate()` | 创建 |
| `xEventGroupSetBits(eg, bits)` | 置位（可多个 bit 一起） |
| `xEventGroupClearBits(eg, bits)` | 清位 |
| `xEventGroupWaitBits(eg, bits, clear_on_exit, wait_for_all, timeout)` | 等位：`wait_for_all=pdTRUE` 要全满足；`pdFALSE` 任一满足 |
| `xEventGroupGetBits(eg)` | 读当前值（不清） |

**返回值**：`xEventGroupWaitBits` 返回等到的那个时刻的完整事件位（不是 0/1），所以可以用 `if (ret & BIT_X)` 判断具体哪个条件满足了。

**和信号量的区别**：

| | 信号量 | 事件组 |
|---|---|---|
| 表达"发生了几次" | 计数信号量可以 | 不行（只有 0/1 的位） |
| 表达"多个条件组合" | 要多个信号量 | **一个事件组搞定** |
| 多个任务等同一事件 | 支持 | 支持（任一任务满足条件就被唤醒） |

**典型用法**："Wi-Fi 连上 && 服务器握手完成 && 传感器就绪" 才启动采集任务。

### 软件定时器

**本质**：定时器服务任务（daemon task）里维护一个定时器列表，到期时**在它自己的上下文里调用你的回调**。

| 本工程配置 | 值 | 含义 |
|---|---|---|
| `CONFIG_FREERTOS_TIMER_TASK_PRIORITY` | **1** | 回调运行在优先级 **1** 的任务里 |
| `CONFIG_FREERTOS_TIMER_TASK_STACK_DEPTH` | 2048 | 回调的栈空间很小 |
| `CONFIG_FREERTOS_TIMER_QUEUE_LENGTH` | 10 | 同时能排队的定时器命令数 |

**这直接决定了三件事：**

1. **回调不能阻塞**（优先级 1，一阻塞全系统定时器都卡）
2. **精度受调度影响**：如果有更高优先级任务长期占 CPU，回调会被推迟
3. **回调里不能调用会阻塞的 API**（`vTaskDelay`、`xQueueReceive(超时)` 都不行）

| API | 用途 |
|---|---|
| `xTimerCreate(name, period, auto_reload, id, callback)` | 创建（`auto_reload=pdTRUE` 周期，`pdFALSE` 单次） |
| `xTimerStart(t, ticks)` / `xTimerStop(t, ticks)` | 启停 |
| `xTimerReset(t, ticks)` | 重新计时（做"按键消抖/看门狗喂狗"常用） |
| `xTimerChangePeriod(t, new_period, ticks)` | 改周期 |

**注意**：这些 API 的第二个参数是"命令排队等待时间"，不是定时器周期——它们只是往定时器任务队列里投一条命令。

**回调原型**：`void cb(TimerHandle_t xTimer)`，可以用 `pvTimerGetTimerID(xTimer)` 拿到创建时传的 id，**一个回调服务多个定时器**。

### 什么时候用软件定时器，什么时候用任务 + vTaskDelayUntil

| 场景 | 选择 |
|---|---|
| 只是"隔一会儿做点小事"（几十毫秒到秒级，非精确） | 软件定时器（省一个任务） |
| 需要精确周期、需要阻塞操作（读 I2C、发网络） | **独立任务 + `vTaskDelayUntil`** |
| 需要周期很短（< 10ms） | 独立任务（定时器任务精度不够） |
| 定时器会动态增删、数量不定 | 软件定时器 |

## 代码

```c
/* ---- 事件组：三个条件全满足才启动 ---- */
#define BIT_WIFI_OK   (1 << 0)
#define BIT_SRV_OK    (1 << 1)
#define BIT_SENSOR_OK (1 << 2)

EventGroupHandle_t eg = xEventGroupCreate();

/* 某个任务里置位 */
xEventGroupSetBits(eg, BIT_WIFI_OK);

/* 等待方 */
EventBits_t bits = xEventGroupWaitBits(eg,
                                       BIT_WIFI_OK | BIT_SRV_OK | BIT_SENSOR_OK,
                                       pdTRUE,        /* 等到后自动清零 */
                                       pdTRUE,        /* 三个都要满足 */
                                       portMAX_DELAY);

/* ---- 软件定时器 ---- */
static void on_timeout(TimerHandle_t t)
{
    /* 这里不能阻塞、不能打大量日志、不能 vTaskDelay */
    int id = (int)(intptr_t)pvTimerGetTimerID(t);
    /* 只做极短的事，比如置一个事件位、给一个信号量 */
    xEventGroupSetBits(s_eg, BIT_TIMER(id));
}

TimerHandle_t t1 = xTimerCreate("t1", pdMS_TO_TICKS(1000), pdTRUE,
                                (void *)(intptr_t)1, on_timeout);
xTimerStart(t1, 0);   /* 0 = 不等待命令排队 */
```

## 易错处

| # | 错误 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 在定时器回调里 `vTaskDelay` / 等队列 | 定时器任务卡死，**所有**定时器全失效 | 回调只置位/发信号量/发通知 |
| 2 | 以为定时器回调在中断里跑 | 上下文判断错误 | 它是**任务上下文**（优先级 1），不是 ISR，不能用 `...FromISR` 的 API |
| 3 | 用事件组的 bit 24~31 | 内核保留位，行为未定义 | 只用 bit 0~23 |
| 4 | `xEventGroupWaitBits` 的 `clear_on_exit` 搞反 | 条件被清掉或永不清 | 一次性触发用 `pdTRUE`；周期检查用 `pdFALSE` |
| 5 | 事件组当计数器用 | 只能表示"有没有"，不能表示"几次" | 用计数信号量 |
| 6 | 定时器周期设 1ms | 精度达不到（tick + 调度延迟） | 短周期用任务 |
