# 06 · 中断级调用与内存管理

## 一句话总结

**中断里只能"通知"，不能"等待"；内存管理的敌人不是"不够"，是"碎片"。**

---

## 概念

### 6.1 中断上下文和任务上下文的区别

| | 任务 | 中断（ISR） |
|---|---|---|
| 能阻塞吗 | 能（睡眠） | **绝对不能** |
| 有 TCB 吗 | 有 | 没有 |
| 能调用 `vTaskDelay` / 带超时的 API | 能 | **不能**（断言崩溃） |
| 需要成对的 API | `xQueueSend` | `xQueueSendFromISR` |
| 栈 | 任务自己的栈 | 中断栈（IDF 里从被中断任务的栈里切一块） |

### 6.2 ISR 里调用 FreeRTOS 的三个固定步骤

```c
BaseType_t higher_prio_task_woken = pdFALSE;

/* ① 用 ...FromISR 版本，第二个参数是出参 */
xQueueSendFromISR(q, &data, &higher_prio_task_woken);
/* 或 vTaskNotifyGiveFromISR(task, &woken);
   或 xSemaphoreGiveFromISR(sem, &woken); */

/* ② 如果唤醒了一个更高优先级的任务…… */
if (higher_prio_task_woken) {
    /* ③ 在中断退出前请求切换，让它立刻跑 */
    portYIELD_FROM_ISR();
}
```

**不写 ③ 的代价**：被唤醒的任务要等到下一个 tick 才运行——tick=1ms 时延迟 1ms，tick=10ms 时延迟最多 10ms。

### 6.3 ISR 里还能做什么、不能做什么

| 可以做 | 不能做 |
|---|---|
| 置事件位（`xEventGroupSetBitsFromISR`，注意它走定时器任务） | `vTaskDelay`、`xQueueReceive(超时)` |
| 给信号量、发通知、发队列 | `malloc`（非 ISR 安全） |
| 读寄存器、做极短计算 | 长时间循环、打大量日志（`ESP_LOGI` 在 ISR 里会卡） |

**经验法则：ISR 里只做"记录 + 通知"，活留给任务干。**

### 6.4 ESP-IDF 的内存分类

| 区域 | 特征 | 放什么 |
|---|---|---|
| **内部 RAM（IRAM/DRAM）** | 快、小（P4 几百 KB） | 栈、队列、DMA 缓冲、中断处理代码 |
| **PSRAM** | 大（板上有 32MB）、稍慢 | 大缓冲（图像、音频、LVGL 帧缓冲） |
| **RTC 内存** | 深睡保持 | 深睡唤醒后要保留的少量状态 |

分配 API：

```c
void *p = heap_caps_malloc(size, MALLOC_CAP_INTERNAL);      /* 必须在内部 RAM */
void *q = heap_caps_malloc(size, MALLOC_CAP_SPIRAM);        /* 可以用 PSRAM */
void *d = heap_caps_malloc(size, MALLOC_CAP_DMA);           /* DMA 能访问的 */
```

**默认的 `malloc`** 在 IDF 里会按配置从默认堆分配（通常优先内部 RAM）——**大块内存一定要显式指定 PSRAM**，否则很可能分配失败。

### 6.5 碎片才是真敌人

```
初始：[        32KB 连续空闲            ]
反复 malloc/free 不同大小后：
      [8K 已用][2K 空][4K 已用][1K 空][6K 已用]…
      总空闲还有 3KB，但最大连续块可能只有 1KB
```

所以嵌入式里两条铁律：

1. **启动时一次性分配，运行期不再 malloc/free**（静态分配 / 预分配池）
2. 需要动态时，只分配**固定大小的块**（内存池），避免碎片

诊断 API：

```c
esp_get_free_heap_size();                 /* 当前空闲总量 */
heap_caps_get_largest_free_block(caps);   /* 最大连续块——比总量更重要 */
heap_caps_get_minimum_free_heap_size();   /* 历史最低水位（判断长期是否泄漏） */
```

### 6.6 栈、堆、以及"谁在吃内存"

| 现象 | 大概率原因 |
|---|---|
| 创建任务返回 `pdFAIL` | 内部 RAM 不够 / 栈要得太大 |
| 网络或图像功能打开后分配失败 | 没走 PSRAM，内部 RAM 被吃光 |
| 运行几天后崩 | 堆碎片或泄漏（看 `minimum_free_heap_size` 是否持续下降） |
| 某个任务莫名重启 | 栈溢出（看 high water mark） |

## 代码

```c
/* ---- ISR 里发通知 ---- */
static void IRAM_ATTR gpio_isr(void *arg)
{
    BaseType_t woken = pdFALSE;
    vTaskNotifyGiveFromISR(s_task_handle, &woken);
    if (woken) {
        portYIELD_FROM_ISR();
    }
}

/* ---- 内存诊断 ---- */
ESP_LOGI(TAG, "空闲总: %u B, 最大连续块: %u B, 历史最低: %u B",
         (unsigned)esp_get_free_heap_size(),
         (unsigned)heap_caps_get_largest_free_block(MALLOC_CAP_INTERNAL),
         (unsigned)heap_caps_get_minimum_free_heap_size());

/* ---- 大缓冲放 PSRAM ---- */
void *fb = heap_caps_malloc(1024 * 600 * 2, MALLOC_CAP_SPIRAM);
if (fb == NULL) {
    ESP_LOGE(TAG, "PSRAM 分配失败");
}
```

## 易错处

| # | 错误 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 中断里用非 ISR 版本 | 断言 → 重启 | 一律 `...FromISR` |
| 2 | 忘了 `portYIELD_FROM_ISR()` | 响应延迟一个 tick | 判断 `woken` 后调用 |
| 3 | ISR 里 `ESP_LOGI` | 串口写可能阻塞，ISR 卡死 | ISR 里只记标志，日志留给任务 |
| 4 | 运行期频繁 malloc/free | 碎片 → 最终分配失败 | 启动期分配，或用固定块内存池 |
| 5 | 大缓冲用默认 malloc | 内部 RAM 被吃光，其他功能挂 | `heap_caps_malloc(..., MALLOC_CAP_SPIRAM)` |
| 6 | 只看"空闲总量" | 看着还有空间却分配失败 | 看 `largest_free_block` |
| 7 | 给任务栈开得过小 | 随机崩溃/花屏 | 用 `uxTaskGetStackHighWaterMark` 实测后再定 |
