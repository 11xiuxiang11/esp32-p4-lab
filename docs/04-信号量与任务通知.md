# 04 · 信号量与任务通知

## 一句话总结

**信号量是"内核里的对象"，任务通知是"写在任务 TCB 里的槽位"——后者更快、更省，但只能一对一。**

---

## 概念

### 三种信号量

| 类型 | 创建 | 语义 | 谁可以 give |
|---|---|---|---|
| 二值信号量 | `xSemaphoreCreateBinary()` | "事件发生了"（0/1） | 任何人（中断也可以） |
| 计数信号量 | `xSemaphoreCreateCounting(max, init)` | "还有 N 个资源/事件" | 任何人 |
| 互斥量 | `xSemaphoreCreateMutex()` | "排他占用" | **只有持有者** |

### 容易混的对比

| | 二值信号量 | 互斥量 |
|---|---|---|
| 初始状态 | **空的**（take 会阻塞） | **可用的** |
| 优先级继承 | 无 | 有 |
| 用途 | 事件通知 | 保护资源 |
| 当锁用会怎样 | 能锁，但会丢继承 → 可能优先级翻转 | 正确 |

### 任务通知（Task Notification）

每个任务在 TCB 里自带一个 **32 位通知值 + 一个"待处理"状态**，**不需要创建任何对象**。

| 操作 | API | 说明 |
|---|---|---|
| 给出通知（任务/ISR） | `xTaskNotifyGive(h)` / `vTaskNotifyGiveFromISR(h, &woken)` | 计数 +1 |
| 接收通知 | `ulTaskNotifyTake(clear_on_exit, timeout)` | `pdTRUE` 取完清零（当二值用）；`pdFALSE` 取完减一（当计数用） |
| 自定义通知值 | `xTaskNotify(h, value, action)` | action 可选 `eSetBits`/`eIncrement`/`eSetValueWithOverwrite` 等 |
| 清空通知值 | `ulTaskNotifyValueClear(h, mask)` | — |

### 信号量 vs 任务通知（面试标准答案）

| 维度 | 信号量 | 任务通知 |
|---|---|---|
| 需要创建对象 | 要（占内存） | **不要** |
| 速度 | 慢（队列 + 等待列表） | **快**（直接改 TCB，约快 45%，FreeRTOS 官方数据） |
| 一对多 | 支持 | 不支持（只能发给指定任务） |
| 多对一 | 支持 | 支持（多个来源给同一个任务） |
| 排队能力 | 有（计数队列） | 只有一个 32 位值 |
| 适用 | 通用、清晰 | 一对一、高频、省内存 |

**选型**：只有一个消费者，且只是"有事件了" → 任务通知；需要多个任务等同一个事件、或需要排队 → 信号量/队列。

## 代码

```c
/* ---- 二值信号量：中断通知任务 ---- */
SemaphoreHandle_t sem = xSemaphoreCreateBinary();     /* 创建即空 */

/* 任务里 */
if (xSemaphoreTake(sem, portMAX_DELAY) == pdTRUE) { 处理事件(); }

/* 中断里 */
BaseType_t woken = pdFALSE;
xSemaphoreGiveFromISR(sem, &woken);
if (woken) { portYIELD_FROM_ISR(); }

/* ---- 计数信号量：资源池 ---- */
SemaphoreHandle_t pool = xSemaphoreCreateCounting(3, 3);   /* 3 个槽，全可用 */
xSemaphoreTake(pool, portMAX_DELAY);   /* 借一个 */
xSemaphoreGive(pool);                  /* 还一个 */
uxSemaphoreGetCount(pool);             /* 还剩几个 */

/* ---- 任务通知：更快的等价物 ---- */
vTaskNotifyGiveFromISR(worker_handle, &woken);   /* 中断里通知 */
ulTaskNotifyTake(pdTRUE, portMAX_DELAY);         /* 任务里等，取完清零 */
```

## 实测（`semaphore_demo.c`）

| 模式 | 预期现象 |
|---|---|
| 0 事件通知（二值信号量） | 创建时计数 = 0；10 次事件一次不丢；唤醒延迟几十微秒 |
| 1 资源池（计数信号量） | 5 个任务竞争 3 个槽，同时占用最大 = **3**，剩余计数回到 3 |

## 易错处

| # | 错误 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 二值信号量创建后直接 take | 永远阻塞 | 先 `give` 一次，或改用互斥量 |
| 2 | 用二值信号量保护资源 | 无优先级继承 | 用 `xSemaphoreCreateMutex()` |
| 3 | 计数信号量 `give` 超过上限 | 失败/断言 | 上限按真实资源数设 |
| 4 | 中断里用非 ISR 版本 | 断言崩溃 | `...FromISR` + `portYIELD_FROM_ISR()` |
| 5 | 在临界区/中断里 `take` | 阻塞 → 死锁/断言 | 中断只 give，不 take |
| 6 | 任务通知用于多对多 | 语义不成立 | 多消费者用队列或信号量 |
